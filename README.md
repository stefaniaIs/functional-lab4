# Лабораторна робота №4 — Рекурсія та мемоізація

**Варіант 3. Найбільший спільний дільник (алгоритм Евкліда).** Іщенко Стефанія, ФеП-22.

## Що реалізовано
`euclid.py` (варіант):
- `gcd_rec` — рекурсивний Евклід. **База:** `gcd(a, 0) = |a|`. **Крок:** `gcd(a, b) = gcd(b, a mod b)`.
- `gcd_iter` — ітеративна альтернатива; `gcd_memo` — з `@lru_cache` (`cache_info()` / `cache_clear()`).
- `ext_gcd` / `ext_gcd_iter` — розширений Евклід: `(g, x, y)` з `a·x + b·y = g` (тотожність Безу).
- `gcd_depth` — глибина рекурсії для пари; `lcm`, `mod_inverse`.
- `trampoline` + `gcd_tramp` — моделювання TCO без росту стеку.

`algorithms.py` (базова частина): чистий 3-шляховий `quicksort` з випадковим pivot,
`Node` + `preorder/inorder/postorder` (рекурсивні генератори), `bfs_level_order`,
`dfs_preorder_iter`, `height`, `fib` з `@lru_cache`, `fib_naive`, `fib_iter`.

## Тести (`pytest -q`, 18 тестів)
Відомі значення та граничні випадки (`0`, від'ємні), збіг із `math.gcd` на 300 випадкових
парах, **тести властивостей** (симетрія, дільність, взаємна простота часток, асоціативність),
тотожність Безу для `ext_gcd`, найгірший випадок глибини, `cache_info/cache_clear`, трамплін,
quicksort проти `sorted`, обходи дерева, Фібоначчі.

## Глибина рекурсії для різних пар (`python main.py`)
| Пара | НСД | Глибина |
|---|---|---|
| 1 000 000, 10 | 10 | 1 |
| 1071, 462 | 21 | 3 |
| 2⁴⁰, 3²⁵ | 1 | 27 |
| F₃₀, F₂₉ | 1 | 28 |
| F₉₀, F₈₉ | 1 | 88 |

Найгірший випадок — сусідні числа Фібоначчі (теорема Ламе): глибина ≤ 5 × (кількість
десяткових цифр меншого числа). Тобто глибина **логарифмічна**, і навіть для 100-значних чисел
гранична глибина ~500 < 1000.

## Час (10 000 викликів, F₉₀ і F₈₉)
| Версія | Час |
|---|---|
| рекурсивна | ~46 ms |
| ітеративна | ~35 ms |
| lru_cache | ~0.7 ms (після першого виклику — кеш) |
| трамплін | ~171 ms (накладні витрати на лямбди) |

Фібоначчі n=25: naive ~6 ms, memo ~0.007 ms, iter ~0.004 ms — мемоізація прибирає
експоненційне повторне обчислення підзадач.

## Ліміт рекурсії та відсутність TCO
CPython має обмеження глибини стеку `sys.getrecursionlimit()` (за замовчуванням 1000);
при перевищенні — `RecursionError`. Хвостова рекурсія (як у `gcd_rec`) **не**
оптимізується (TCO немає за задумом розробників — щоб зберігати повні traceback'и), тож кожен
виклик займає кадр стеку. Ітеративна версія безпечніша, коли глибина може бути великою або
невідомою (дерева на мільйони вузлів тощо). Для НСД глибина логарифмічна, тому рекурсія тут
безпечна, але ітерація все одно трохи швидша.
